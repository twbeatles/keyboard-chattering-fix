## 1. P0 — 당장 구현할 것

### P0-1. 간격 히스토그램 영속화 (+ 측정 기준 변경 시 초기화)

#### 문제

이 프로젝트의 차별점인 **권장 기준 자동 계산**과 **"스위치 점검" 진단**은 키별 간격 히스토그램(`gap_hist`)으로 계산한다. 그런데 이 히스토그램만 디스크에 저장되지 않는다.

| 데이터 | 저장 여부 | 근거 |
|---|---|---|
| 전체 타건·차단 수 | 저장 (`iTotalPresses`·`iBlockedPresses`) | `storage.rs:275-284` |
| 키별 타건·차단 수 | 저장 (`stat.XX=presses,blocked`) | `storage.rs:285-296`, 쓰기 `:349-356` |
| 키별 간격 히스토그램 | **저장 안 함**. 기동 때마다 0 | `debounce.rs:118-141` `Debouncer::new`, `bootstrap.rs:35-64` `init_shared`에 복원 코드 없음 |

그래서 다음과 같은 일이 생긴다.

1. **재시작마다 진단이 처음부터 다시 시작된다.** 상주 앱이고 `--autostart`로 매 로그인마다 새로 뜨므로, 사실상 "오늘 쓴 만큼만" 보고 판단한다.
2. **채터는 드물게 일어나는 사건이다.** 하루에 몇 번 튀는 스위치는 하루치 표본으로는 군집이 잘 안 보인다. `recommend`는 키당 표본 20개(`MIN_SAMPLES`)가 쌓여야 판단을 시작하고, 군집은 그보다 더 많이 쌓여야 뚜렷해진다(`recommend.rs:14-22`).
3. **화면에서 눈에 띄는 불일치가 생긴다.** [키·마우스] 탭은 행을 고를 때 영속화된 `blocked`를 보고(`keys_page.rs:121-123`) 권장 열은 히스토그램을 본다(`:118`). 그래서 재시작 직후에는 "차단 300회"인 키가 **"데이터 부족"**으로 나온다. 사용자는 기능이 고장 났다고 느낀다.

여기에 **이미 있는 잠재 버그**가 하나 겹친다. 실행 중에 측정 기준(`sMeasureFrom`)을 `release` ↔ `press`로 바꾸면, `record_gap`(`debounce.rs:151`)이 이전 기준과 새 기준의 간격을 **한 히스토그램에 섞는다**. 두 기준은 간격의 의미가 다르다(press 기준은 키를 누르고 있던 시간까지 포함한다). 그래서 섞인 히스토그램으로 낸 권장값은 어느 쪽에도 맞지 않는다. 지금은 재시작하면 지워져서 피해가 하루로 끝나지만, **영속화하면 영구적으로 남으므로 이 두 가지를 반드시 함께 고쳐야 한다.**

#### 왜 P0인가

- 기능 결함에 가깝다. 핵심 기능(권장값)이 상주 앱의 실제 사용 패턴(매일 재시작)에서 제대로 동작하지 않는다.
- 위험이 작다. 훅 핫패스는 바뀌지 않는다(이미 `record_gap`으로 증가만 한다). 바뀌는 곳은 UI 스레드의 저장·로드 경로뿐이다.
- 모든 다른 진단 기능(P2-2 추이, P2-5 일괄 적용)의 토대가 된다.

#### 설계

**저장 형식** — 0이 아닌 버킷만 쓰는 희소 형식. 0이 아닌 키만 쓴다(`stat.XX`와 같은 규칙).

```ini
sHistMeasure=release
hist.41=0:3,1:2,3:1,12:5,18:40,40:312
hist.20=2:1,16:20,40:900
```

- `hist.<2자리 16진 vk>=<버킷>:<개수>,...` — 버킷은 0~40(`GAP_BUCKETS = 41`, 40은 200ms 이상 넘침 칸).
- `sHistMeasure` — 히스토그램을 모은 측정 기준. 로드할 때 `sMeasureFrom`과 다르면 히스토그램 전체를 버린다(파일을 손으로 고친 경우의 방어).
- 크기: 보통 60키 × 버킷 15개 × 약 8바이트 ≈ 7KB. 최악(256키 × 41버킷 × 최대 자릿수)도 100KB 아래다. 5분 자동 저장은 `LiveFingerprint`(`settings_form.rs:270-274`)가 같으면 건너뛰고, 히스토그램은 타건이 있어야만 바뀌므로 `total`이 바뀌는지로 충분히 판별된다.
- 파싱은 관대하게 한다. 형식이 틀린 항목, 버킷 ≥ 41, 숫자가 아닌 값은 그 항목만 무시한다(기존 `stat.XX`와 같은 태도). 개수는 `u32`, 넘치면 `u32::MAX`로 포화시킨다.

**소유권** — 히스토그램은 `stat.XX`처럼 **라이브 필터가 원본**이다(파일 원본인 `key.XX`와 반대). 그래서 `adopt_file_only_fields`(`model.rs:56-67`)에는 넣지 않고, 저장할 때마다 `Debouncer`에서 복사한다.

**흩어진 복사 지점 정리** — 지금 라이브 카운터를 `Settings`로 옮기는 코드가 세 곳에 복붙되어 있고, 복원은 한 곳이다.

| 위치 | 하는 일 |
|---|---|
| `settings_form.rs:263-269` `persist_with` | 라이브 → Settings |
| `settings_form.rs:~505-508` `on_save` | 라이브 → Settings |
| `files.rs:141-147` `import_settings` | 라이브 → 가져온 Settings("이 PC의 통계는 유지") |
| `bootstrap.rs:45-48` `init_shared` | Settings → 라이브 |

히스토그램을 여기에 하나씩 더하면 네 곳을 고쳐야 하고, 다음 카운터가 생길 때 또 빠뜨리기 쉽다. 그래서 다음 두 함수로 묶는다.

```rust
// config/model.rs
impl Settings {
    /// Counters and measured gaps owned by the live filter.
    pub fn take_live_stats(&mut self, d: &Debouncer) { /* total, blocked, per_key_*, gap_hist */ }
}
// debounce.rs
impl Debouncer {
    pub fn restore_stats(&mut self, s: &Settings) { /* 반대 방향 */ }
    /// Measured gaps mean something else under another baseline.
    pub fn clear_gap_histograms(&mut self) { ... }
}
```

`Settings`에는 `pub gap_hist: Box<[GapHistogram; 256]>`(약 42KB)과 `pub hist_measure: MeasureFrom`를 더한다. `Settings`는 `Clone`이므로 그대로 동작한다. `Default`는 0으로 채운 상자를 만든다(`Debouncer::new`와 같은 `vec!` → `try_into` 패턴).

**측정 기준이 바뀔 때** — `on_save`에서 이전 `measure_from`과 새 값이 다르면, `SHARED` 락 안에서 `set_measure_from` 직후 `clear_gap_histograms()`를 부른다. `hist_measure`는 새 값으로 저장한다. 키별 타건·차단 수는 의미가 바뀌지 않으므로 그대로 둔다.

**선택: 오래된 표본 감쇠** — 히스토그램이 무한히 쌓이면, 스위치를 청소한 뒤에도 예전 채터가 계속 권장값에 남는다. 지금은 "이 키 통계 지우기"(`clear_key_stats`, `debounce.rs:196`)로 해결할 수 있다. 자동으로 하려면, 저장 시(UI 스레드) 한 키의 합계가 예를 들어 50,000을 넘을 때 그 키의 모든 버킷을 반으로 줄이면 된다. 최근 표본의 비중이 유지되고 훅에는 영향이 없다. **1차 구현에서는 빼고**, 필요하면 후속으로 넣는 것을 권한다.

#### 핫패스·락 영향

- 훅: 변화 없음.
- `persist_with`는 `SHARED` 락 안에서 42KB를 복사한다. 메모리 복사 수 µs 수준이고 5분 자동 저장·종료·키 탭 변경 때만 일어난다. 그래도 CLAUDE.md의 "UI 쪽 락 구간을 짧게"를 지키기 위해 **복사만 락 안에서 하고, 직렬화(`format!`)는 락 밖**에서 한다(지금 구조가 이미 그렇다. `config::save`는 락을 놓은 뒤 호출된다).

#### 테스트 (개수 채우기가 아니라 경계·폴백 위주)

| 테스트 | 기대 |
|---|---|
| `storage`: 히스토그램 왕복 | 저장 후 로드하면 `gap_hist`가 같다. 0인 키는 줄이 없다 |
| `storage`: 잘못된 항목 | `hist.41=0:3,99:5,x:1,2:y,3:4` → 버킷 0=3, 3=4만 남는다 |
| `storage`: 기준 불일치 | `sMeasureFrom=press` + `sHistMeasure=release` → `gap_hist`가 전부 0 |
| `storage`: 손상 판정 | `hist.` 줄만 있는 파일도 설정 파일로 인정된다(`looks_like_settings`) |

| `debounce`: 복원 후 권장 | 채터 군집이 있는 히스토그램을 `restore_stats`하면 `recommend`가 `Suggest`를 낸다 |

| 구 버전(≤0.3.4)으로 되돌렸을 때 | 모르는 키(`hist.`, `sHistMeasure`)는 무시된다. 다음 저장에서 사라질 뿐 손상은 없다 |
| 설정 파일이 커져서 직접 편집이 불편해짐 | 히스토그램 줄을 파일 **맨 끝**에 쓰고, 그 앞에 `; measured gaps (written by the app)` 주석 한 줄을 둔다 |
| 설정 내보내기 파일에 히스토그램이 포함됨 | 가져오기는 이미 "이 PC의 통계 유지"이므로 동작은 맞다. 내보내기에서 빼고 싶다면 `stat.`과 함께 빼는 것이 일관적이다(현재는 둘 다 포함) |

예상 작업량: 코드 약 120줄 + 테스트 약 100줄. 하루 이내.

## 2. P1 — 다음 릴리스

### P1-1. 키·버튼별 "필터 안 함" (`key.XX=0`)

- **현재**: 키별 기준은 1~1000ms로 클램프된다(`storage.rs:302`, `settings_form.rs:288`, `Debouncer::set_key_threshold`). 그래서 **특정 키만 필터에서 빼는 방법이 없다.** 1ms로 두는 것이 최선이다.
- **필요한 경우**:
  - 게임의 더블 탭 대시, 리듬 게임 연타 키
  - 마우스 필터를 켰을 때 오른쪽·가운데 버튼은 빼고 왼쪽만 막고 싶을 때
  - IME 전환 키, 원격 도구용 키(KeyboardChatterBlocker 이슈 #55의 우회책이 "그 키를 0으로")
- **구현**: 클램프를 `0..=1000`으로 바꾸고 0은 "필터 안 함"으로 정의한다. `judge_down`의 `gap < effective_threshold(vk)`(`debounce.rs:399`)는 기준이 0이면 항상 거짓이므로 **판정 코드는 바뀌지 않는다**. 통계는 계속 센다. 키·마우스 탭에 "필터 안 함" 체크(또는 0 입력 허용)와 표시 문구("끔")를 더한다. 전역 기준은 1 이상을 유지한다.
- **테스트**: `key.20=0` 로드 → `Some(0)`, 0ms 기준 키에서 2ms 간격 Down이 통과하고 `total_presses`는 증가.

### P1-2. 마우스 버튼 기본 기준 분리 (`iMouseThreshold`)

- **현재**: `bFilterMouse`를 켜면 버튼에 키보드 전역 기준(기본 50ms, 뗀 순간 기준)이 그대로 적용된다(`strings.rs:291` 안내 문구가 이를 설명한다).
- **문제**: 더블클릭의 "뗌 → 다음 누름" 간격은 빠른 사용자의 경우 40~80ms다. 그래서 **켜자마자 더블클릭이 씹히는 사용자가 생긴다.** 안내 문구는 "목록에서 낮추라"고 하지만, 처음 켜는 순간에는 그 버튼이 목록에 아직 없다(차단이 한 번 일어나야 나타남, `keys_page.rs:121-123`).
- **구현**: `iMouseThreshold`(기본 30ms 권장, 0 = 전역 기준 따름)를 추가하고, `effective_threshold`에서 vk 0x01~0x06이면 `per_key → mouse → global` 순서로 고른다. 마우스 스위치 옆에 숫자 입력 하나를 둔다(`layout::SPECS` 한 줄).
- P1-1과 같은 릴리스에 묶으면 "마우스는 왼쪽 버튼만 30ms, 나머지는 끔" 같은 설정이 UI만으로 가능해진다.

### P1-3. 시간 제한 일시 중지

- **현재**: 보호는 켜기/끄기 토글뿐이다(`commands.rs:50` `set_protection`, 트레이 `MENU_TOGGLE`). 게임 한 판, 화면 녹화 중에 끄고 **다시 켜는 것을 잊는 경우**가 흔하다. 상태 알약과 회색 트레이 아이콘이 있지만 놓치기 쉽다.
- **구현**: 트레이 메뉴에 "일시 중지 ▸ 15분 / 1시간 / 다시 켤 때까지"를 추가한다. 기존 `suspended`(앱이 정한 일시 중지)와 별개로 `pause_until: Option<Instant>`를 UI 상태로 두고, 500ms 타이머가 만료를 확인해 복귀시키며 풍선 알림을 띄운다. 청소 모드 자동 종료(`cleaning_tick`, `commands.rs:91`)와 같은 패턴이다. 홈 화면 안내에 "14:32까지 일시 중지"를 표시한다(`stats::render_stats`의 `note` 분기에 추가, 순수 함수라 단위 테스트 가능).
- 만료 판정은 `cleaning_expired`처럼 순수 함수로 만든다.

### P1-4. 기록·CSV 시각에 날짜 포함

- **현재**: 기록 시각은 `START_CLOCK_MS`(기동 시각의 하루 중 ms) + 단조 경과 시간으로 `HH:MM:SS.mmm`을 만든다(`history.rs:69` `format_clock`, 자정에 0으로 돌아감). CSV(`render_csv`, `:198`)도 같다.
- **문제**: 상주 앱은 며칠씩 켜져 있고 기록은 최대 5000건(`LOG_LIMIT_MAX`)이다. **여러 날에 걸친 기록에 날짜가 없어** CSV를 수리·RMA 문의 증빙으로 쓰기 어렵다. 또한 기동 시점의 벽시계에 경과 시간을 더하는 방식이라 서머타임 전환이나 시계 동기화 뒤에는 표시가 어긋난다(절전 중 `Instant`가 흐르는지에 따라 절전 뒤에도 어긋날 수 있다. 실측 필요).
- **구현**: 훅은 지금처럼 `Duration`만 기록한다(핫패스 불변). 표시할 때 **현재** 벽시계 기준으로 거꾸로 계산한다. 즉 `wall_now − (START.elapsed() − e.time)`. UI 스레드에서 `GetLocalTime`을 한 번 부르면 된다. 기록 탭은 오늘이 아닌 행에만 날짜를 붙이고, CSV는 항상 `YYYY-MM-DD HH:MM:SS.mmm`로 쓴다. 변환은 순수 함수로 만들고, 기존 `clock_formats_and_wraps_past_midnight` 테스트를 날짜 경계 테스트로 바꾼다.

### P1-5. 배포 신뢰 (코드와 무관, 병행)

- **코드 서명**: `scripts/build_release.ps1`에 `signtool` 경로가 이미 있다. 서명되지 않은 키보드 훅 프로그램은 SmartScreen 경고와 백신 오탐을 가장 많이 받는 범주다. 오픈소스 무료 서명(SignPath Foundation)이나 Azure Trusted Signing 신청을 권한다. 서명은 업데이트 헬퍼에도 적용한다.
- **winget 제출**: `packaging/winget/` 매니페스트는 준비되어 있고 아직 제출하지 않았다(README). 서명과 함께 제출하면 검증 통과가 쉬워진다.

## 3. P2 — 여유가 있을 때

### P2-1. 마우스 휠 역스크롤(엔코더 채터) 필터

- 마모된 휠 엔코더는 아래로 굴리는데 위로 한 칸씩 튀는 증상을 낸다. 클릭 채터 다음으로 흔한 마우스 고장이고, KeyboardChatterBlocker가 지원한다. 지금은 `mouse_button`이 휠을 `None`으로 걸러 통과시킨다(`hook.rs:233-252`, 테스트 `:912`).
- **구현**: `WM_MOUSEWHEEL`(세로)만 대상으로 한다. 직전 휠 이벤트와 **방향이 반대**이고 간격이 N ms(기본 80ms) 미만이면 차단한다. 같은 방향은 항상 통과시킨다. 상태는 방향과 시각 두 값뿐이라 무할당이다. 고정 크기 상태를 `Debouncer` 옆에 두고, 판정은 `fn wheel_decision(prev, now, delta) -> bool` 순수 함수로 만든다. 옵션(`bFilterWheel`, 기본 끔)과 통계(`VK` 대신 별도 카운터)를 둔다.
- 주의: 정밀 터치패드·고해상도 휠은 `delta`가 120의 배수가 아니다. 방향 부호만 보면 된다. 수평 휠(`WM_MOUSEHWHEEL`)은 제외한다.

### P2-2. 스위치 상태 추이와 열화 알림

- 지금 통계는 **누적값 하나**라 "최근에 나빠졌는지"를 알 수 없다. 스위치는 서서히 나빠지므로 추이가 진단 가치가 크다.
- **구현**: 하루 단위로 키별 (타건, 차단) 증분을 최근 30일만 저장한다(`day.YYYYMMDD=vk:p:b,...`, 또는 별도 `history.ini`). 기록 탭 "키별 통계"에 "최근 7일 차단률"과 이전 대비 화살표를 둔다. 어떤 키의 최근 차단률이 크게 오르면(예: 하루 20회 이상, 이전 7일 평균의 3배) 트레이 풍선으로 한 번 알린다("A 키 스위치 상태가 나빠지고 있어요").
- P0-1(히스토그램 영속화)과 같은 저장 경로를 쓰므로 그 뒤에 한다.

### P2-3. 자동 업데이트 확인 (선택)

- 지금은 메뉴·트레이·CLI로 **수동 확인만** 한다(`spawn_update_check`의 호출자는 `commands.rs:180` 하나). 상주 앱 사용자는 보안·버그 수정판을 놓친다.
- **구현**: `bAutoCheckUpdate`(기본 켬 권장, 끌 수 있음), 마지막 확인 시각 `iLastUpdateCheck`. 기동 1분 뒤 + 이후 7일마다 워커 스레드에서 확인한다. 새 버전이 있으면 대화상자 대신 **트레이 풍선만** 띄우고, 누르면 기존 확인 흐름으로 간다. 패키지 관리자 설치본과 관리자 실행은 기존 `update_route`가 그대로 안내한다.
- 판정(`due(last, now, interval)`)은 순수 함수로 만든다.

### P2-4. 실행 중 인스턴스 CLI 제어

- AutoHotkey·Stream Deck·작업 스케줄러에서 `KeyboardChatteringFix.exe --toggle`, `--pause 15m`, `--resume`, `--cleaning`으로 실행 중 인스턴스를 제어할 수 있게 한다.
- **구현**: 두 번째 실행은 단일 인스턴스 검사(`app::instance`) 뒤에 기존 창을 찾아 `WM_COPYDATA`로 명령을 보내고 종료한다. 받는 쪽은 `commands::run`으로 넘긴다.
- **보안**: 같은 사용자의 다른 프로세스는 이미 `SendInput`과 창 메시지로 같은 일을 할 수 있으므로 새 위협은 아니다. 다만 `WM_UPDATE_EXIT`의 nonce 사례처럼 **종료·업데이트 같은 파괴적 명령은 열지 않고**, 켜기·끄기·일시 중지·청소만 허용한다. 관리자 인스턴스는 UIPI 때문에 일반 권한 프로세스의 메시지를 받지 못하므로 `ChangeWindowMessageFilterEx`로 `WM_COPYDATA`만 허용할지 결정해야 한다(허용하지 않는 쪽을 권장, 문서화).

### P2-5. 권장값 일괄 적용

- [키·마우스] 탭은 키를 하나씩 골라 **적용**한다. 처음 쓰는 사용자는 권장이 붙은 키가 여러 개일 때 반복 작업이 된다.
- "권장값 모두 적용" 버튼: `Advice::Suggest`인 키만, 지금 기준보다 **높이는** 경우만 적용하고, 적용 전에 목록을 보여 확인을 받는다. 한 번의 `persist_with`로 저장한다(키마다 `set_key_override`를 부르면 파일 쓰기가 키 수만큼 일어난다). 선택할 키 계산은 순수 함수로 만든다.

### P2-6. 보호를 끄거나 일시 중지하는 순간의 보류된 뗌

- 떼기 확인(`iReleaseDeferMs`) 중에 보호가 꺼지거나(`set_protection(false)`) 자동 일시 중지가 걸리면(`foreground.rs:248`), 훅은 그 뒤 이벤트를 `decide_event`에 넘기지 않는다(`hook.rs:216`, 마우스 `:268-271`). 그런데 보류된 뗌은 타이머가 나중에 주입한다. 그래서 그 사이(최대 100ms)에 같은 키를 다시 누르면 순서가 **누름(통과) → 예전 뗌(주입)**이 되어, 사용자가 누르고 있는 키가 앱에서는 떼어진 것으로 보인다.
- 창이 매우 좁아(전환 순간 + 100ms 이내) 실사용 빈도는 낮다. 청소 모드 시작에서 이미 쓰는 방식(`commands.rs:74` `flush_deferred_releases()`)을 보호 끄기와 일시 중지 진입에도 적용하면 된다. 몇 줄이면 되고 기존 `flush_deferred_releases_empties_pending` 테스트 패턴을 재사용할 수 있다.

## 4. P3 — 장기 과제

### P3-1. 키보드 배열 히트맵·키 테스트 화면

- 지금 진단은 목록(기록 탭·키 탭)뿐이다. 키보드 배열 그림에 키별 차단률을 색으로 칠하면 문제 키가 한눈에 보인다.
- "키 테스트" 모드를 두어, 누를 때마다 그 키가 빛나고 마지막 간격을 보여 주면 스위치 교체 후 확인용으로 좋다.
- 오너드로 위젯이 이미 있지만(`ui/widgets.rs`), 배열 정의(ANSI/ISO/JIS, 한국어 106키)와 레이아웃·DPI 처리 비용이 크다. 렌더 좌표 계산은 순수 함수로 두어 테스트한다.

### P3-2. 앱별 프로필

- 지금 앱별 동작은 "일시 중지"뿐이다(`sAutoDisableApps`). "게임에서는 30ms, 그 밖에서는 50ms" 같은 요구에는 앱별 기준이 필요하다.
- 전경 감지(`foreground::tick`)가 이미 있으므로, 앱 이름 → 기준 맵을 두고 전경이 바뀔 때 `Debouncer`의 전역 기준만 바꾸는 방식이 가장 단순하다. 다만 설정 UI가 복잡해지므로 P1-1(키별 끄기)·P1-3(시간 제한 일시 중지)로 대부분의 요구가 해결되는지 먼저 본다.

### P3-3. 언어 추가

- 언어 레지스트리와 컴파일러가 안내하는 추가 절차(`language.rs` 상단 주석), 번역 누락 테스트(`strings.rs`)가 준비되어 있다. 기술 비용은 작고 번역 품질이 관건이다.
- 채터링 도구의 수요가 큰 순서로 일본어 → 중국어 간체 → 독일어를 권한다. 업데이트 오류 문구(`updater/error.rs`)도 함께 번역해야 한다.

### P3-4. Per-Monitor DPI v2

- 지금은 시스템 DPI 인식이다(`build.rs:60` `dpiAware=true`). 배율이 다른 모니터로 창을 옮기면 비트맵 확대로 흐려진다.
- `WM_DPICHANGED` 처리, 폰트·GDI 캐시 재생성, `sc()`의 DPI를 창 단위로 바꾸는 작업이 필요하다. 레이아웃이 논리 좌표 표(`layout::SPECS`)로 되어 있어 구조적으로는 준비되어 있지만, 주의점이 많아(오너드로·더블버퍼·`WS_CLIPCHILDREN`) 수동 검증 비용이 크다.

| 권장값 **자동** 적용(묻지 않고 바꿈) | 기각 | 정상 연타를 막는 방향으로 기준이 오르면 사용자는 원인을 모른다. P2-5처럼 확인 후 일괄 적용으로 충분하다. |

## 6. 진행 순서 제안

1. **P0-1 히스토그램 영속화** — 단독 PR. 저장 형식이 정해지면 P2-2가 같은 길을 쓴다.
2. **P1-1 + P1-2** — 키별 끄기와 마우스 기준. 같은 `effective_threshold` 주변을 고치므로 한 PR로 묶는다.
3. **P1-3, P1-4, P2-6** — 각각 작고 독립적이다.
4. **P1-5** — 코드와 무관하므로 신청 절차를 지금 시작해 두면 위 작업과 병행된다.
5. 그다음 **P2-3 → P2-5 → P2-1 → P2-2 → P2-4** 순서.

릴리스 전에는 기존 게이트(`fmt`·`clippy -D warnings`·`check --workspace`)와 `scripts/e2e`(특히 `hook_session_e2e`·`features_e2e`)를 실행한다. 새 가시 문자열은 모든 언어에 넣는다(`strings.rs` 테스트가 강제).
